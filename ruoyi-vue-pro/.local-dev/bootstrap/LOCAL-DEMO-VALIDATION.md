# 本地演示数据与验证边界

此目录的演示数据由当前公开 Java DO、服务逻辑和本地 uni-app DIY 组件接口推导并原创编写。没有使用受限 SQL、外部演示数据库、供应商商品、品牌授权、真实报价或客户记录。

商品名称、页面公告和商品占位图均明确标注“本地演示 / 非卖品 / LOCAL DEMO / NOT FOR SALE”。金额与库存仅用于测试代码行为，不代表可售商品或真实交易能力。

## 使用顺序

1. 建立独立本地测试库，并导入仓库自带基础 system/infra SQL；不要把这些脚本用于现有生产库。
2. 导入同目录 `generated-mall-schema.sql`，补足从公开实体推导的 72 张业务表。
3. 导入 `local-demo-seed.sql`。脚本使用事务与固定高位 ID，可以重复导入；重复执行会把这些演示 ID 的名称、测试价格、库存等重置到初始值。
4. 用现有本地启动脚本运行已启用会员、商品、营销、交易等模块的后端。
5. 素材目录是同目录 `assets`；静态资源服务仅绑定 `127.0.0.1:48081`。SQL 中的素材地址固定为这个本机地址，不访问第三方图床。

生成器 `generate_demo_seed.py` 可重新生成 SQL 和原创 SVG/PNG。它会读取本地 DO 与微信编译产物 `app.json`，校验种子列和页面路由；它不会连接或写入数据库。

## DIY 页面与真实路由

首页使用 `NoticeBar`、`SearchBar`、`TitleBar`、`ProductCard`；商品卡片采用现有 `twoCol` 变体和真实 SPU ID。

我的页使用 `NoticeBar`、`UserCard`、`UserOrder`、`MenuList`。底部导航指向现有首页、分类、购物车、我的四条路由。所有配置 URL 已对本地编译产物注册路由核对，未知路由数为 0。

未修改前端源码。这些配置用于建立原版功能基线，不代表用户已经审核过的最终视觉设计。

## 公开接口验证

以下测试仅访问本机公开 API；预期是业务 `code=0`，不能仅以 HTTP 200 判定通过。

```sh
curl --noproxy '*' -sS -H 'tenant-id: 1' \
  'http://127.0.0.1:48080/app-api/promotion/diy-template/used'

curl --noproxy '*' -sS -H 'tenant-id: 1' \
  'http://127.0.0.1:48080/app-api/product/spu/page?pageNo=1&pageSize=10'

curl --noproxy '*' -sS -H 'tenant-id: 1' \
  'http://127.0.0.1:48080/app-api/product/spu/get-detail?id=880000000401'

curl --noproxy '*' -sS -H 'tenant-id: 1' \
  'http://127.0.0.1:48080/app-api/trade/order/settlement-product?spuIds=880000000401,880000000402,880000000403'
```

核验：

- 默认模板编号是 `880000000600`，返回 `property.tabBar`、`home.components`、`user.components`。
- 商品分页能找到 3 条“本地演示样品”；详情 A 的 SKU 是 `880000000501`，价格为 `100` 分，库存为测试值 `100`，规格数组非空。
- 商品结算信息仍引用同一组 SPU/SKU，原价与活动计算结果应一致，因为本脚本未创建促销活动。
- 首页、分类、商品详情应显示明显的演示标记，素材从 `127.0.0.1:48081` 加载。

## 登录后验证与边界

购物车 `/trade/cart/add`、`/trade/cart/list` 和订单 `/trade/order/settlement` 需要有效的本地会员。不能使用管理后台登录令牌替代会员令牌，也不能把缺少会员或鉴权的错误当成价格引擎失败。

使用正常的本地会员登录流程后，可添加 SKU A 数量 1、SKU B 数量 2，验证购物车和结算商品总价为 `500` 分。结算请求需要 `pointStatus=false`；接口允许未选收件地址时先计算，最终创建订单仍需合法地址等字段。脚本不会生成真实地址或自动提交订单。

本脚本没有支付应用、支付渠道、供应商接口、跨境报关、承运商或真实优惠券数据。即使展示、购物车和金额计算通过，也只证明“本地后端在原创演示数据上执行了现有代码”；不能据此宣称真实微信登录、支付、优惠券核销、供应商发货或物流履约已经联调完成。
